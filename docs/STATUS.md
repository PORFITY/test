или осознанно посчитать по ориентирам.

## Что работает (по ТЗ)

Геолокация «при использовании» + ручной адрес; радиусы 500 м…50 км и свой; авто-расширение радиуса; карта, фильтры (расстояние, сеть, тип, каталог), выбор любого числа магазинов;
бюджет любой положительной суммы; период 1…365 дней; любое число людей и приёмов пищи (с переименованием); профили людей; обязательный вопрос об аллергенах (10 стандартных + свои),
строгое исключение по справочнику и по составу товара (включая «может содержать»), неизвестный состав помечается; нежелательные/любимые (поиск + свободный текст);
цели питания; техника и посуда (с объёмом) — блюда, невозможные на вашем оборудовании, не предлагаются, есть альтернативные способы (духовка → плита); вместимость посуды → «в N подходов»;
рацион с учётом упаковок/остатков/сроков годности/заморозки/этапов закупок; 4 режима покупок; сравнение цен по магазинам; подробные рецепты (граммовки + бытовые меры, шаги, таймеры),
режим «Готовить» с прогрессом и таймерами, пересчёт порций; список покупок (группы по магазину и дню, «куплено» → в запасы, экспорт текст/CSV); «Мои продукты» со сроками;
статистика и фактические расходы; история; избранное; свои рецепты; замена блюд; ассистент (локальные команды + AI через backend); напоминания; удаление всех данных; офлайн-доступ к сохранённому.

## Ограничения и нереализованное (без приукрашивания)

* **Нет интеграций с каталогами конкретных сетей** (см. выше). Цены/наличие/акции конкретных магазинов появляются только из перечисленных источников.
* **Уведомления об изменении цен**: переключатель в настройках есть, самой отправки нет — нет источника достоверных обновлений цен.
* **Библиотека — 46 рецептов и 57 ингредиентов** (русская кухня «бюджетного» уровня). Этого достаточно для разнообразной недели, но для 60-дневного рациона блюда неизбежно повторяются (штраф за повторы это сдерживает, но не отменяет).
* **Питательная ценность** считается по справочным значениям для сырых продуктов (типичные таблицы), а не по конкретному товару; данные с упаковки используются только для проверки аллергенов. Потери/привес при готовке не моделируются.
* **Общее меню:** ограничения каждого человека объединяются; отдельные блюда для отдельных людей не составляются (если у одного аллергия — блюдо исключается для всех).
* **Оптимизация — эвристика (локальный поиск + точный подбор упаковок), а не MILP.** Это сознательный выбор ради работы на телефоне офлайн; оптимальность меню не доказывается. Подбор упаковок для одного продукта — точный (DP), для очень больших количеств — «лучшая упаковка + точный остаток».
* **Сопоставление «товар → ингредиент»** — правила по ключевым словам и исключениям; редкие названия могут не распознаться (такие товары отбрасываются, а не угадываются).
* **Размеры порций** — по энергетической потребности (формула Миффлина–Сан Жеора при введённых параметрах) или стандарт 2000 ккал. Это не медицинская рекомендация; приложение не гарантирует безопасность при медицинских ограничениях.
* **Хранилище** — защищённый JSON-файл, а не SwiftData/Core Data (обоснование в ARCHITECTURE.md).
* **Подписанный IPA не выпущен** (нет ваших сертификатов). Есть неподписанный IPA из CI и инструкция сборки/установки через Xcode.
* Интерфейс на русском; локализации нет. Только iPhone, портрет.
* На реальном iPhone приложение мной не запускалось (нет устройства); проверено сборкой и UI-тестом в симуляторе на CI. Визуальная вёрстка на разных размерах экрана вручную не проверялась.
